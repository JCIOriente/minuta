# Chapters — Implementation Plan

- Spec: docs/specs/2026-10-25-chapters.md
- Date: 2026-10-25
- Status: in backlog

## Overview
New logic goes in a new module, `src/chapters/`: the chapter types and stamps (T1), answer
parsing, snapping and the chapter rules (T3), prompts, schema and the artifact (T4). Existing
modules change only where the spec requires it:
- `fields`: the filled `chapters` field (T2).
- `template`: `output: chapters` frontmatter (T5) and the built-ins (T8, T9).
- `template::graph` and `runner`: dependencies become a list (T6).
- `generate`: the chapters template step and filling the field (T7).

T1 creates `src/chapters/` with the shared types and empty submodules, makes three private
fields helpers `pub(crate)` so `chapters::validate` and `chapters::prompt` can reuse them, and
adds the test fixture `tests/fixtures/whisper/class.json`. After T1, no other task edits
`src/lib.rs` or `src/chapters/mod.rs`.

Leaf tasks are decoupled through plain function signatures:
- `chapters::validate` takes segments and the end time, not a `Transcript` or a job.
- `chapters::{prompt, render}` only need the T1 types.
- `fields` only needs `chapters::{Chapter, lines}` from T1.

T7 joins them in the template step, reusing `call_json`, `generate_with` and the repair loop
of `generate_fields` (`src/generate.rs:238`). T9 switches the built-in `youtube` to the field,
which needs the whole stack. T10 adds the integration suite and the e2e.

Shared interfaces, fixed here so parallel tasks agree. Private helpers can be added freely.
A change to a public shape requires updating this plan in the same PR.

```rust
// chapters/mod.rs (T1)
pub mod prompt; pub mod render; pub mod validate;
pub const CHAPTERS_VERSION: u32 = 1;
pub const NAME: &str = "chapters";               // the template name
pub const JSON_FILE: &str = "chapters.json";
pub const MIN_CHAPTERS: usize = 3;
pub const MIN_SECONDS: u64 = 10;                 // per chapter
pub const MIN_TRANSCRIPT_SECONDS: u64 = 30;      // MIN_CHAPTERS * MIN_SECONDS
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub struct Chapter { pub start: u64, pub title: String }   // key order start, title
#[derive(Debug, Clone, Copy, Default, PartialEq, Eq)]
pub struct ChaptersSpec { pub max: Option<usize>, pub max_chars: Option<usize> }
/// `h:mm:ss`, `hh:mm:ss`, `m:ss`, `mm:ss`; seconds 0-59; minutes 0-59 when hours are given;
/// checked arithmetic. `None` for anything else.
pub fn parse_stamp(s: &str) -> Option<u64>;
/// `m:ss` below 3600, `h:mm:ss` from 3600.
pub fn stamp(seconds: u64) -> String;
/// `<stamp> <title>` per chapter joined with "\n", no trailing newline. What `max_chars` measures.
pub fn lines(chapters: &[Chapter]) -> String;

// fields/validate.rs (T1): visibility only, no behavior change
pub(crate) fn parse_object(text: &str) -> Result<serde_json::Map<String, serde_json::Value>, String>;
pub(crate) fn normalize(text: &str) -> String;  // the existing normalization (control chars, CRLF, trim), src/fields/validate.rs:150
// fields/prompt.rs (T1)
pub(crate) const REPAIR_INTRO: &str;

// fields/mod.rs (T2)
pub enum Field { Title, Body, Tags, Hashtags, ThumbnailText, Chapters }
pub enum Kind { Text, List, Chapters }
impl Field {
    pub const ALL: [Field; 6];                   // existing order, Chapters appended
    pub fn is_filled(self) -> bool;              // true only for Chapters
}
pub enum Value { Text(String), List(Vec<String>), Chapters(Vec<Chapter>) }  // rendered(): chapters::lines
impl FieldsSpec { pub fn declares_chapters(&self) -> bool; }
impl Values {
    /// Inserts `Value::Chapters(chapters)` at the declared position of `chapters`; unchanged
    /// when the spec does not declare it.
    pub fn fill_chapters(self, spec: &FieldsSpec, chapters: Vec<Chapter>) -> Values;
}
// parse_answer, fields_block, schema: same signatures; filled fields are skipped.

// chapters/validate.rs (T3)
/// `answer` is already cleaned by `call::clean`. `end` = last segment end, floored. Snaps, then
/// checks the rules; all violations in one pass, in the spec's order.
pub fn parse_answer(answer: &str, segments: &[Segment], end: u64, spec: &ChaptersSpec)
    -> std::result::Result<Vec<Chapter>, Vec<Violation>>;

// chapters/prompt.rs (T4)
pub fn chapters_block(spec: &ChaptersSpec) -> String;                     // no language instruction
pub fn repair_system(spec: &ChaptersSpec, output_lang: &str) -> String;   // REPAIR_INTRO + block + language instruction, last
pub fn schema() -> serde_json::Value;
// chapters/render.rs (T4)
pub fn markdown(chapters: &[Chapter]) -> String;                          // lines() + "\n"
pub fn artifact_json(output_lang_code: &str, chapters: &[Chapter]) -> String;  // ADR-0009, pretty, trailing newline
pub struct Artifact { pub output_lang: String, pub chapters: Vec<Chapter> }
/// Errors are the spec's wording after "chapters.json": "has version 2, which this version of
/// minuta cannot read", or the parser message.
pub fn read_artifact(text: &str) -> std::result::Result<Artifact, String>;

// template/mod.rs (T5)
pub enum Output { Markdown, Fields(FieldsSpec), Chapters(ChaptersSpec) }

// template/graph.rs (T6)
/// `None` = unknown template; `Some(deps)` = the templates it reads, in order (empty: transcript).
type DepsOf<'a> = &'a dyn Fn(&str) -> Option<Vec<String>>;
pub fn order(requested: &[String], deps_of: DepsOf) -> Result<Vec<String>>;
pub fn dependents(order: &[String], of: &str, deps_of: DepsOf) -> Vec<String>;
// runner.rs (T6): deps = the `input` template if any, then "chapters" when Output::Fields declares it.
```

## Contract
No HTTP API of minuta's own. Public contracts and owners:
- Frontmatter `output: chapters` and its `limits` (ADR-0004, ADR-0008): T5. The `chapters`
  field in `fields` and its rules: T2.
- `chapters.json` layout and `chapters.md` (ADR-0009): T4 builds them, T7 writes them.
- The `chapters` value inside `<name>.json` (ADR-0009): T2.
- `templates list` OUTPUT value `chapters`: T5. The built-in row: T8.
- The Ollama `format` schema for chapters calls: T4. The fake server records request bodies
  already.

## Impact
- **`Field`, `Kind`, `Value`** (shared, exhaustive matches in `src/fields/{prompt,validate,render}.rs`
  and `src/template/mod.rs:253`): T2 adds the variants and every arm in one PR. The fields
  block and schema of templates without `chapters` must stay byte-identical: the existing
  exact-string tests in `src/fields/prompt.rs` and `tests/templates.rs` stay green unchanged.
  The "unknown field (known: …)" message gains `chapters` at the end; its test is updated in T2.
- **Fingerprints** (`src/generate.rs:99`): markdown templates and fields templates without
  `chapters` must not change. T7 first pins both on `main` (fixed expected values), then
  changes the code.
- **Call cache**: no key changes. `complete` and `complete_json` keys are already pinned by
  sub-project 3 tests (`src/llm/call.rs`), which must stay green.
- **Template graph** (`src/template/graph.rs`, callers at `src/runner.rs:244` and `:296`):
  `order` and `dependents` keep their results for single-input graphs. Existing graph unit
  tests and `tests/integration/templates.rs` stay green (T6).
- **Reserved names** (`src/template/mod.rs:71`): `chapters` leaves the list. The
  reserved-names test (`tests/templates.rs:360`) is updated in T5.
- **Output enum**: T5 adds `Output::Chapters` with a temporary arm in `src/generate.rs` that
  returns a template error ("output chapters is not supported yet"); T7 replaces it. No
  built-in uses the variant until T8, so no user path reaches the stub in between.
- **Built-in youtube** (T9): its fingerprint changes, so existing job folders rerun youtube
  (intended, spec "Data & migrations"). `-t youtube` now needs a transcript of 30 s or more:
  every hermetic youtube test moves to `class.json`.
- **CLI output**: tests asserting exact `templates list` output, reserved names or youtube
  prompt text are listed in the Touches of the owning task: `tests/cli.rs` (T8),
  `tests/templates.rs` (T2, T5, T8, T9), `tests/integration/templates.rs` (T6),
  `tests/integration/fields.rs` (T9, T10).
- `job.json`: no schema change.
- Rollout and rollback: one release. Reverting the merges restores sub-project 3.
  `chapters.json`/`chapters.md` left in job folders are ignored by the older binary, which
  would rerun youtube with its old built-in.
