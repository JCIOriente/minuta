# Chapters (sub-project 4 of 6) — Spec

- Status: approved
- Date: 2026-10-25
- Owner: Arnold Gandarillas Castillo
- Related: docs/brief.md (Chapters, Media pipeline, Templates), docs/specs/2026-10-24-templates-and-backends.md,
  docs/specs/2026-10-25-fields-and-social-templates.md, ADR-0003 to ADR-0009, issues #22, #54

## TL;DR
- A new built-in template, `chapters`, with a new output kind `output: chapters`. It reads the
  transcript (30 s `[hh:mm:ss] text` blocks), asks the model for `[{start, title}]` as JSON,
  snaps each start to a segment start and checks YouTube's chapter rules (ADR-0008).
- Two problems are fixed in code: starts are snapped, and the first chapter moves to 0:00. Every
  other broken rule (fewer than 3, out of order, shorter than 10 s, over a limit) goes back to
  the model in a repair call, as for fields (ADR-0006). Only accepted answers are cached.
- It writes `chapters.json` (versioned, whole seconds) and `chapters.md` (`0:00 Title` lines,
  paste-ready) (ADR-0009). `input: chapters` reads `chapters.md`.
- A fields template can declare the field `chapters`. minuta fills it from `chapters.json`,
  never from the model, and the template then depends on `chapters`. The built-in `youtube`
  does this: its description gets real chapters instead of the placeholder line.
- `FIELDS_VERSION` and the fields artifact version stay 1. A new `CHAPTERS_VERSION` covers the
  chapter prompts, rules and rendering.

## Change in a nutshell
```
$ minuta run clase.mp4 -t youtube
[1/8] probe       cached
…
[6/8] summary     ollama:gemma4:26b  1 call  51.0s
[7/8] chapters    ollama:gemma4:26b  2 calls  31.7s
[8/8] youtube     ollama:gemma4:26b  1 call  14.3s
minuta-out/clase
$ cat minuta-out/clase/chapters.md
0:00 Introducción
4:12 Qué es ownership
17:40 Borrowing y referencias
38:05 Ejercicios y cierre
```
`chapters` took 2 calls: in the first answer the second chapter started 4 s after the first, so
minuta asked the model to merge or move it. `chapters.json`:
```json
{
  "version": 1,
  "output_lang": "es",
  "chapters": [
    { "start": 0, "title": "Introducción" },
    { "start": 252, "title": "Qué es ownership" },
    { "start": 1060, "title": "Borrowing y referencias" },
    { "start": 2285, "title": "Ejercicios y cierre" }
  ]
}
```
The built-in `youtube` template now declares `fields: [title, body, chapters, tags,
thumbnail_text]`, so `youtube.md` has the description followed by a blank line and the four
chapter lines above, ready to paste into YouTube. `youtube.json` holds the same list under
`fields.chapters`. Today the youtube prompt asks the model to end the description with a
placeholder such as `[Agregar capítulos con marcas de tiempo]`
(`src/template/builtin/youtube.md:17`), and `chapters` is a reserved name
(`src/template/mod.rs:73`) and a rejected field (`src/template/mod.rs:213`). After this change
the description carries real timestamps that YouTube turns into chapters.

## Problem
YouTube builds chapters from timestamp lines in the description. Writing them by hand means
scrubbing through an hour-long class. The bash pipeline left a placeholder, and sub-project 3
kept it. Models given a transcript can propose topic boundaries, but local models round,
invent or reorder timestamps, and YouTube silently ignores the whole list when one rule
breaks (first at 0:00, at least 3, each at least 10 s, ascending). The YouTube publisher
(sub-project 6) and the edit plan (sub-project 5, which remaps timestamps) need chapters as
data, not text.

## Goals / Success criteria
1. `minuta run a.mp4 -t chapters` writes `chapters.json` and `chapters.md` and records
   `templates.chapters` with both artifacts in `job.json`.
2. `minuta run a.mp4 -t youtube` runs `summary`, `chapters`, then `youtube`, in that order.
   `youtube.json` has `fields.chapters` equal to the `chapters` list of `chapters.json`, and
   `youtube.md` renders the chapter lines between the body and the tags.
3. Every start in `chapters.json` is the whole-second floor of a transcript segment start,
   except the first, which is 0. A model start that is not a segment start is snapped to the
   nearest one (test with exact values).
4. Each chapter rule under "Validation" is a violation with the exact message listed there,
   and a repair call sends it to the model (one test per rule). If the repaired answer passes,
   `chapters` is done with 2 calls.
5. When every answer breaks a rule, `chapters` fails (exit 1) after `1 + llm.repairs` answers,
   writes no artifact, and `youtube` does not run. The next run makes a new final call while
   map calls stay cached (request count checked).
6. A transcript that ends before 30 s fails `chapters` before any call, with the message under
   "Behavior & edge cases".
7. Requests to Ollama for the chapters final and repair calls carry the chapters JSON schema in
   `format`. Map calls do not. With chunked input only the consolidation call asks for JSON.
8. The model is never asked for the `chapters` field of a fields template: it is absent from
   the fields block and from the Ollama schema of `youtube` (exact strings checked).
9. A second identical run makes zero requests. Regenerating `chapters` with different content
   reruns `youtube`; identical content does not. `--force chapters` reruns `chapters` and
   `youtube`, not `summary`.
10. Fingerprints of `markdown` templates and of fields templates without `chapters` do not
    change (fixed expected values), so sub-project 2 and 3 job folders stay cached, except
    `youtube`, whose built-in file changes.
11. Every frontmatter error listed under "Behavior & edge cases" exits 2 before any step runs,
    with a message that names the template (one test per error).
12. `templates list` shows `chapters` with INPUT `transcript` and OUTPUT `chapters`;
    `templates show chapters` prints the built-in file.
13. Chapter titles follow the output language: the final and repair prompts end with the
    language instruction from sub-project 2. If a fields template's output language differs
    from the one recorded in `chapters.json`, it fails with the message under "Behavior & edge
    cases".
14. No test contacts a real LLM or the network. The opt-in e2e (`MINUTA_E2E_LLM=1`) checks the
    YouTube rules on real output.

## Non-goals
- Remapping chapters through an edit plan, and captions changes (sub-project 5).
- Uploading chapters or checking YouTube's character rules for titles, such as `<` and `>`
  (sub-project 6).
- A `{{chapters}}` template variable. Templates get chapters through `input: chapters` or the
  `chapters` field.
- `output: chapters` on templates with another name, or several chapter lists per job.
- Chapter lists in the `linkedin` and `instagram` built-ins.
- Chapter descriptions, nested chapters, per-title length limits (the list's `max_chars`
  bounds the total), or a minimum title length.
- Measuring the last chapter against the media duration from `probe`. The transcript end is
  used (see "Validation").
- Cutting, merging or reordering chapters in code. Only the model changes the list, apart from
  the two fixes under "Snapping".
- Items in #22 and #54.

Security notes:
- Model answers are untrusted. They are parsed with `serde_json` into typed values. Titles get
  the fields normalization (control characters other than `\n` and `\t` removed, `\r\n` to
  `\n`), then every whitespace run, newlines included, becomes one space, and the title is
  trimmed. A title therefore cannot break the one-chapter-per-line format.
- Starts are parsed with checked arithmetic. A start with too many digits is a violation, not
  an overflow.
- Titles are only written to files, never printed, except inside violation messages, which
  reach the terminal only through `render_error` (sanitized).
- A project `./templates/chapters.md` is untrusted like any project template: the containment
  rules from sub-project 2 apply, and its frontmatter is parsed with typed,
  `deny_unknown_fields` structs.
- The off-machine note is unchanged: `chapters` on `claude` prints
  `note: chapters sends its input to claude (Anthropic)`.

## Tenancy & localization
- Tenancy: n/a.
- Output language rules from sub-project 2 are unchanged. `chapters` resolves its output
  language like any template (`--output-lang` > its `lang:` > `llm.output_lang` > detected).
  Titles are written in it. JSON keys stay English.
- Timestamps are offsets from the start of the joined media, in whole seconds (floor). They are
  not clock times, so time zones do not apply.
- Rendered stamps follow YouTube: `m:ss` below one hour (`0:00`, `4:12`, `59:59`), `h:mm:ss`
  from one hour (`1:00:00`, `1:02:03`). Each line is formatted on its own.
- minuta adds no fixed text in any language to chapter output.

## Domain model
New and updated terms in `CONTEXT.md`: Chapters, Chapter, Chapter line, Chapter rules,
Snapping, Filled field; Template, Field, Fields template and Violation are updated.

### The `chapters` template (ADR-0008)
Built-in `src/template/builtin/chapters.md`, prompt written in English:
```markdown
---
description: Timestamped chapters (YouTube rules)
input: transcript
output: chapters
limits:
  chapters: { max: 20, max_chars: 1500 }
---
Divide the recording "{{job_name}}" ({{duration}}) into chapters by topic, for the YouTube
description. Start a chapter where the speakers move to a new topic, not at every pause. Each
title names the topic in a few words that a viewer would recognize. Use only topics that are
in the input.
```
Frontmatter rules for `output: chapters`:
- Only the template named `chapters` may declare it, and the template named `chapters` must
  declare it.
- `input` must be `transcript` (the default). Snapping needs the segments.
- `limits` is optional and may contain only the key `chapters`, with `max` (chapter count) and
  `max_chars` (length of the chapter lines joined with `\n`), each an integer. `max` must be at
  least 3, `max_chars` at least 1. Without a limit there is no cap.
- `fields` and `format` are not allowed. `description`, `llm` and `lang` work as for any
  template.

### Chapter
`{ start: u64 seconds, title: String }`. A valid list (after snapping and validation) has:
first start 0, at least 3 chapters, strictly ascending starts, each chapter at least 10 s long
(the last one up to the transcript end), non-empty single-line titles, and the template's
limits met.

### Model answer
```json
{ "chapters": [ { "start": "00:04:12", "title": "Qué es ownership" } ] }
```
`start` is a string `h:mm:ss`, `hh:mm:ss`, `m:ss` or `mm:ss`. Seconds are 0–59; minutes are
0–59 when hours are given and 0–99 otherwise; hours have 1 or 2 digits. Numbers or other forms are violations.

### Snapping
After parsing, before validation, in this order:
1. Each start is replaced by the start of the nearest transcript segment (ties go to the earlier
   segment), then floored to whole seconds. Segments with empty text count. A start before the
   first segment snaps to it.
2. The first chapter's start becomes 0.

Snapping never reorders, drops or merges chapters, so the violations below describe what the
model wrote, with snapped times.

### Validation
All violations in one pass. Times in messages are rendered stamps of the snapped starts, and
"the end" is the transcript end: the last segment's end, floored to whole seconds (the same
value as `{{duration}}`). The exact messages:
1. Not an object: `the answer is not a JSON object (<parser message>)` (the fields wording and
   the same fallback from the first `{` to the last `}`).
2. `missing key "chapters"`
3. `"chapters" must be a list of objects` (not an array, or an item that is not an object)
4. Per chapter n (1-based), in order:
   `chapter 2: missing "start"`, `chapter 2: "start" must be a time like "00:04:12"`,
   `chapter 2: missing "title"`, `chapter 2: "title" must be a string`,
   `chapter 2: "title" is empty`.

Rules 5–9 are checked only when rules 1–4 found nothing.

5. `there are 2 chapters; YouTube needs at least 3.`
6. `there are 24 chapters; the limit is 20. Merge related chapters to keep at most 20.`
7. Per chapter that starts before the previous one:
   `chapter 3 ("Borrowing") starts at 4:12, before chapter 2 at 5:00. List the chapters in the
   order they happen.`
8. Only when rule 7 found nothing, per chapter shorter than 10 s:
   `chapter 1 ("Introducción") lasts 4 s (0:00 to 0:04); each chapter must last at least 10 s.
   Merge it with a neighboring chapter or move a start.` For the last chapter the bracket reads
   `(12:04 to the end at 12:10)`. Two chapters with the same snapped start make the first one
   last 0 s.
9. `the chapters are 1612 characters as rendered; the limit is 1500. Use fewer chapters or
   shorter titles.`

No violations: the list is accepted.

### Prompts
- **Final call** (single call, or consolidation when chunked): system = rendered body +
  (chunked: the consolidation sentence) + the chapters block + the language instruction. The
  chapters block for the built-in limits:
  > Return only a JSON object with one key, "chapters", and no text before or after it.
  > "chapters" is an array of objects, one per chapter, in the order they happen:
  > "start" (string): when the chapter starts, copied from a timestamp in the input, like
  > "00:04:12". The first chapter starts at "00:00:00".
  > "title" (string): the chapter title, on one line, in plain text without Markdown.
  > Give at least 3 and at most 20 chapters. Each chapter lasts at least 10 seconds. As
  > "0:00 Title" lines, all chapters together have at most 1500 characters.
  > Keep the keys exactly as written, in English; write the titles in the language given below.

  Without `max` the sentence reads "Give at least 3 chapters."; without `max_chars` the
  "As "0:00 Title" lines…" sentence is left out.
- **Map calls** are unchanged. Their task already says "keeping timestamps", so the
  consolidation input carries timestamps.
- **Repair call**: system = the fields repair intro ("You correct a JSON object. Fix only the
  problems listed in the input, keep everything else unchanged, and return only the corrected
  JSON object.") + the chapters block + the language instruction. User = the fields
  `repair_user` text (`Previous answer:\n…\n\nProblems:\n- …`). It does not resend the
  transcript.
- **Schema** sent to Ollama:
  `{"type":"object","properties":{"chapters":{"type":"array","items":{"type":"object","properties":{"start":{"type":"string"},"title":{"type":"string"}},"required":["start","title"]}}},"required":["chapters"]}`.
  `serde_json` writes object keys in sorted order, so the bytes sent have `properties` and `required` before `type`; the content is the same.
  No length or count constraints.
- `CHAPTERS_VERSION` (new constant, starting at 1) is bumped when the chapters block, the
  repair prompt, parsing, snapping, the rules or chapter-line rendering change. It is part of
  the fingerprint of the `chapters` template and of every fields template that declares the
  `chapters` field. `PROMPT_VERSION` and `FIELDS_VERSION` are not bumped.

### Template step
- Calls go through `chunk::generate_with` with the chapters block and a final-call hook that
  runs the repair loop, like `generate_fields` (`src/generate.rs:238`). Final and repair calls
  use `call_json` with the chapters schema; its `accept` parses, snaps and validates. A cache
  hit is accepted again the same way (ADR-0006).
- Artifacts: `chapters.json` then `chapters.md`, each with `write_atomic`. Done if and only if
  both exist (as for fields templates).
- Fingerprint = the sub-project 2 parts (the input is `transcript.json`) + `CHAPTERS_VERSION`.
- Progress and call counting are the same as for fields: `repair 1/2` on the spinner, and
  repair calls counted in `N calls`.

### Chapters artifact (ADR-0009)
```json
{ "version": 1, "output_lang": "<code>", "chapters": [ { "start": <u64>, "title": "<string>" } ] }
```
Pretty-printed by `serde_json` with keys in this order and a trailing newline. Readers reject an
unknown `version` and any other shape. `chapters.md` is the chapter lines joined with `\n`, plus
a trailing newline.

### The `chapters` field (filled field)
- `chapters` joins the shared field set as a third kind, `chapters`. It is a filled field:
  minuta takes its value from `chapters.json`, and the model never writes it.
- A fields template that declares it:
  - depends on the template `chapters`, besides its `input`. The graph gains a second edge
    (dependencies are: the `input` template if any, then `chapters`).
  - must declare at least one other field, and may not put a limit on `chapters` ("the
    chapters field is limited in the chapters template").
  - leaves `chapters` out of the fields block, the Ollama schema and answer validation. After
    the answer is accepted, the value from `chapters.json` is inserted at its declared
    position.
  - adds the content hash of `chapters.json` and `CHAPTERS_VERSION` to its fingerprint.
- Rendering: `plain` prints the chapter lines; `markdown` prints them as a list
  (`- 0:00 Introducción`). In `<name>.json`: `"chapters": [{"start": 0, "title": "…"}, …]`.
- The fields artifact keeps `version: 1`: adding a field is additive (ADR-0006, ADR-0007), and
  no reader of version 1 exists yet besides minuta.

## Behavior & edge cases
- **Frontmatter errors** (exit 2 at resolution, each naming the template):
  `output: chapters` on a template not named `chapters`; a template named `chapters` without
  `output: chapters`; `output: chapters` with an `input` other than `transcript`; `fields` or
  `format` with `output: chapters`; a `limits` key other than `chapters`; a key under
  `limits.chapters` other than `max` and `max_chars`; `max` below 3; `max_chars` of 0; a
  fields template whose only field is `chapters`; a limit on the `chapters` field of a fields
  template.
- **Short transcript**: a non-empty transcript that ends before 30 s fails before any call:
  `template chapters: the transcript ends at 0:25; YouTube chapters need at least 30 s (3
  chapters of at least 10 s). To run a template that declares the chapters field on it,
  override it in ./templates without that field.` Templates that need `chapters` do not run.
  Templates earlier in the order have already run and stay done.
- **Empty transcript**: `template chapters: transcript is empty`, as in sub-project 2.
- **Repairs exhausted / `llm.repairs = 0` / interrupt during a repair**: as for fields
  templates. No artifact, not marked done, rejected answers not cached.
- **Language mismatch**: a fields template that declares `chapters`, whose output language
  differs from `output_lang` in `chapters.json`, fails (exit 1) before any call:
  `template youtube: chapters.json is in es but youtube writes en; give both templates the same
  lang, or use --output-lang`. This only happens when one of them sets `lang:`.
- **`chapters.json` unreadable**: missing → `template youtube: input chapters.json is missing`;
  unknown version → `template youtube: chapters.json has version 2, which this version of
  minuta cannot read`; other damage → `template youtube: chapters.json: <parser message>`. An
  I/O error other than not-found names the path (conventions).
- **Answer with extra keys** (in the object or in a chapter): ignored.
- **Chunked input**: map calls as in sub-project 2; the consolidation call asks for JSON.
- **User override without limits**: allowed. A chapter list may then exceed the youtube budget,
  and the YouTube upload check in sub-project 6 catches it.

## Decisions
- ADR-0008: Chapters come from a built-in template with output kind `chapters`, reach fields
  templates as a filled `chapters` field that adds a graph edge, are snapped and moved to 0:00
  in code, and are otherwise repaired by the model.
- ADR-0009: `chapters.json` is a versioned list of whole-second starts and titles;
  `chapters.md` holds YouTube chapter lines; the fields artifact keeps version 1.
- Relied on: ADR-0001 (no new flags), ADR-0003 and ADR-0005 (fingerprints, call cache, the
  `templates` map), ADR-0004 (frontmatter), ADR-0006 (repair loop, accepted-only caching,
  rendered-length budgets), ADR-0007 (fields artifact).
- `CONTEXT.md` gains Chapters, Chapter, Chapter line, Chapter rules, Snapping, Filled field;
  Template, Field, Fields template and Violation are updated.

## FAQ
### Why a built-in template and not a fixed stage or a pipeline step?
As a template, chapters reuse the graph, fingerprints, the call cache, `--force`, backend and
language precedence, `templates list|show` and overriding by file. A pipeline step would need a
backend on every `run`, and the closed `StepName` enum (ADR-0005). A fixed stage would need its
own copies of all of these.

### Why does minuta fill the `chapters` field instead of the model?
Models drop, round or reorder timestamps when they copy them. The list in `chapters.json` has
already passed YouTube's rules, so copying it in code keeps it valid. It also keeps the youtube
call small.

### Why snap and move the first chapter in code, but repair everything else?
Snapping and the first start have one right answer that needs no judgment. Merging a short
chapter, choosing which of 24 to drop, or reordering needs to know what the chapters are about,
so the model does it. This is the ADR-0006 rule that minuta never rewrites content.

### Why does `chapters` read the transcript and not `summary`?
Snapping needs segment starts, and summaries do not keep reliable timestamps. For a long
recording this means the transcript is chunked twice (by `summary` and by `chapters`).

### Why whole seconds?
YouTube reads chapter times in whole seconds from the description text, so the rules must hold
on whole seconds. Storing what YouTube sees avoids a second rounding in the publisher.

### Why a static 3450/1500 split of the description?
It is the ADR-0006 rule: fields add up to the platform total. A body limit computed from the
chapters at run time would change the youtube prompt and cache key whenever chapters change,
and would add a limit kind that depends on another artifact.

### Why fail on recordings under 30 s instead of writing no chapters?
An empty list would be a valid chapters value everywhere (artifact, rendering, `input:
chapters`). Short clips are rare for this tool, and the error says how to run youtube without
chapters.
